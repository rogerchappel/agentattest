# AgentAttest Orchestration

AgentAttest is intentionally local-first. The orchestration contract describes the repeatable release-candidate workflow a maintainer or agent should run before publishing a branch.

## Workflow

1. Install dependencies with `npm ci`.
2. Run `npm run release:check`.
3. Run `bash scripts/validate.sh`.
4. Exercise the CLI in a temporary git repository:

   ```sh
   tmpdir="$(mktemp -d)"
   cd "$tmpdir"
   git init -b main
   git config user.email agentattest@example.com
   git config user.name AgentAttest
   printf '# demo\n' > README.md
   git add README.md
   git commit -m "initial"
   node /path/to/agentattest/dist/src/cli.js init
   printf 'changed\n' >> README.md
   git add README.md
   git commit -m "change"
   node /path/to/agentattest/dist/src/cli.js collect --since HEAD~1
   node /path/to/agentattest/dist/src/cli.js verify agent-attestation.json
   node /path/to/agentattest/dist/src/cli.js markdown agent-attestation.json
   ```

## Release Classification

- `ship-ready`: release checks pass, CLI smoke passes, docs disclose limitations, and no known blocker remains.
- `incubating`: implementation exists but verification, packaging, documentation, or safety boundaries have unresolved blockers.
- `blocked`: core CLI flow cannot run or produces misleading output.

## Artifacts

- `agent-attestation.json`: local receipt generated by `agentattest collect`.
- Markdown receipt: rendered by `agentattest markdown` and suitable for pull request notes.
- `RELEASE_NOTES.md`: current release-candidate summary and verification record.
- `docs/orchestration.json`: machine-readable release workflow metadata.
